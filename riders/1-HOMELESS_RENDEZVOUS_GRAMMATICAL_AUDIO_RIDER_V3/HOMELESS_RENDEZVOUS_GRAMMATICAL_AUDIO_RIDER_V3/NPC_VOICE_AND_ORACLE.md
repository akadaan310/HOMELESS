# NPC SPEECH / ORACLE ARM64 / PLAYER VOICE — engineering specification

## 1. Voice should sound authored, not procedural filler

Speech can be generated by a small neural TTS model without having an LLM *decide the words*. Separate:

`WorldEvent -> Grammar/Act Planner -> Validated utterance -> Optional tiny paraphraser -> Grammar/Fact revalidation -> TTS -> Encoded audio -> Hash -> Spatial mixing`.

A TTS model is neural inference but is not a general-purpose generative language model. The primary text-to-meaning engine remains existing `Ingram` grammar × in-grammar and world canonical facts. Optional tiny neural language models propose surface phrasing only. A failed rewrite is rejected and the deterministic original is spoken.

The source of truth is NPC's own state: beliefs, relations, availability, goals, current world revision and authorized dialogue acts. A sentence must carry `speaker_actor, voice_id, speaker_style, locale, semantic_act, canonical_content, utterance_variant_id, source_context_hash, exact_text, provenance`.

## 2. Practical baseline on reported `ollama-a1` (ARM64 Neoverse, 2 vCPU, 11 GiB RAM, 9.2 GiB free)

**These machine specs come from Muse's report, not verified in this session. Measure actual installed resources before scheduling synthesis.** Existing Ollama, PURL tunnel, PostgreSQL and Codex must remain responsive. Never schedule full corpus synthesis at startup. Use `ionice`/CPU limits/concurrency budget and a bounded work queue; prefer **one synthesis worker** initially. Store compressed voice clips on cheap object storage/CDN or an approved existing store, not indefinitely on a nearly full boot disk.

### Preferred TTS contenders (actual audio quality to be measured)

- **Piper**: https://github.com/OHF-Voice/piper1-gpl . Small ONNX local TTS voices; test `en_US` variants and `ar_JO-kareem-medium` or low for Arabic/Jordanian speech. Real sample quality, pronunciation, CPU latency and locale coverage determine per-character selection. Official voice manifest supports Arabic/Jordanian. `en_US-arctic-medium` can supply a multi-speaker family, but voices must be distinguished by model/speaker indexes, not pitch-shift tricks alone.
- **Kokoro 82M**: https://huggingface.co/onnx-community/Kokoro-82M-v1.0-ONNX . Evaluate ONNX quantized CPU rendition as higher-quality English contender; on 2 vCPU ARM64 the cold-start/real-time factor may be too slow; reserve first for offline batch rendering. Voice samples must be judged perceptually and benchmarked. Not a promise of real-time speed.
- **sherpa-onnx**: https://github.com/k2-fsa/sherpa-onnx . Unified offline ASR/TTS/VAD runtime on ARM64, Android and WebAssembly, useful to standardize interfaces; benchmark exact model before treating it as a Piper/Kokoro quality replacement.
- **eSpeak NG**: deterministic/low-footprint diagnostic fallback for voice availability checks only; not the cinematic release voice standard.

### Oracle voice roles

`SPEECH_COMPOSER`: consumes approved discourse acts (not raw spontaneous hallucinated story); uses deterministic variants or optional tiny model; emits fully grounded text. `TTS_JOBBER`: a bounded isolated process synthesizing prioritized unseen utterances. `AUDIO_PACKER`: normalizes loudness, trims silence, aligns subtitles and optional viseme timings, encodes a browser-capable codec (Opus when verified, AAC as required), hashes and stores. `VOICE_CATALOG`: immutable source clips and metadata with cache keys and language variants. `GAME_GATE_SCHEDULER`: predicts near-future phrases and preloads only required clips; phone never waits synchronously for synthesis.

Suggested `speech_asset` record:
```
{
 "kind":"npc_speech", "text":"That light changed before you arrived.",
 "locale":"en-US", "voiceId":"npc-amber-03", "model":"piper", "modelRevision":"PINNED",
 "pronunciationRevision":"PHONEMES_HASH", "prosody":{"style":"curious","rate":1.0},
 "semanticAct":"notice-street-light", "utteranceRevision":2,
 "cacheKey":"SHA256(CANONICAL_INPUT)", "audioHash":"SHA256(ENCODED_BYTES)",
 "codec":"opus", "sampleRate":24000, "durationMs":1470,
 "subtitle":"That light changed before you arrived.", "state":"ready"
}
```
Illustrative numbers and hashes above are *schema examples, not measured output.* Do not use voice imitations of real strangers or people whose voice was not authorized.

### Pre-generation layers

- **Baseline world bed**: neighborhood crowd/murmur, multiple language ambiences, aircraft, weather, footsteps, shop/vehicle sound beds. Stream/loop licensed recordings or synthesized effects separately from semantic dialogue.
- **High-frequency phrase packs**: typical greetings, refusals, curiosity, thanks, situational acknowledgments and question forms, per speaker family and language.
- **Scene-episode bundles**: a pair/group NPC conversation script from an accepted world state trajectory; generate clips and subtitles for admissible branches, but committing which branch happens remains the world's decision.
- **Just-in-time**: only newly confirmed NPC-specific lines, modeled as asynchronous jobs with a deterministic no-voice fallback for deadline misses; put the highest fidelity packs near Tampa prewarm entry cache.
- **Multilingual**: explicit accent/locale and phoneme dictionary. Arabic orthography and diacritization may require locale-specific normalization and pronunciation; preserve original text, transliteration only as pronunciation hint, not as truth source.

### Exact cache identity

`voiceKey=sha256(canonical({text, locale, phoneme_version, tts_model, weights_hash, voice_id, speaker_index, speaking_rate, emotion_style, output_format, sample_rate}))`.
Audio waveform equality is not presumed across floating-point backends unless measured; cache stored bytes with independent content hash. Separate voice identity from actor identity and voice clip ID from game event ID.

## 3. Smallest optional language model

**First candidate:** `ollama run smollm2:135m-instruct-q4_0` (135M parameters) or `smollm2:135m` (271MB reported), with `smollm2:360m` as a more capable but costlier comparison. The Ollama library reports 135M, 360M and 1.7B families (https://ollama.com/library/smollm2); exact quantized variants should be pinned after benchmarks. Candidate selection is not a performance guarantee.

Its *only* job: rewrite `CanonicalAct(text + named slots)` into a short natural utterance, honoring controlled speaker style. It may not invent new proper names, places, witnesses, dates, relationships, missions, or state mutations. Run grammar/entity/slot consistency checks after generation; if failed or timed out, use deterministic template result. No LLM is needed for initial playable world. Real-time path must survive with this model completely disconnected.

Benchmarks on the actual Oracle node: cold/warm prompt processing, tokens/s, p50/p95 per 1-sentence variant, RAM usage, effect on Ollama/PURL/database service, failure/grounding rate, and number of simultaneously cached voices. Don't schedule the LLM in the main audio thread; precompute while idle.

## 4. Player speech input

Flow: `mic consent -> browser/Android capture -> push-to-talk/VAD -> STT hypothesis+confidence -> discourse act recognizer -> grammar+glossary -> clarification if ambiguous -> authorized event -> NPC response`. Default push-to-talk so background conversation isn't silently harvested. An explicit opt-in local/on-device mode is ideal where feasible.

`sherpa-onnx` supports streaming/nonstreaming ASR, VAD, Android, WASM, ARM64; use model availability and measured accuracy to decide between local on-device and remote Oracle recognition. An optional `whisper.cpp` tiny/base multilingual model is a candidate, but compare its latency and correct transcription for both colloquial English and Arabic in the intended noise conditions. Browser speech recognition, if used, may depend on external processing; always keep a keyboard/tap fallback and never claim offline when dependent on a cloud browser API.

STT never executes shell commands or PURL/SEURL writes directly; language can request an *intent* which the game validates and authorizes. Keep exact text and canonical act distinct. When confidence low, respond in-world with a short clarifying exchange, not a loud global modal popup. Record transcripts only with the configured user option and bounded retention; run baseline gameplay without any mic permission.

## 5. Actual world sound mix

PlayCanvas positional SoundComponent + listener, optionally lower-level WebAudio graph for filters/reverb/ducking. Voices have `position`, `orientation`, `audibilityRange`, `occlusion`, `gain`, `priority`, `speechGroup`, `worldTimestamp`, `subtitles`. Natural nearby conversations should be overheard sideways and sometimes missed. Add credible distance attenuation, geometry-aware filtering and room transitions, background/foreground mix, and speech/music ducking—not all NPCs speaking simultaneously into a globally centered audio bus.

Scene sound has **responsive** and **leading** components: a far-off balloon performance may lead Dark toward the gathering (audible direction, changing intensity); his movement alters mix continuously. Effects may be measured for opt-in game design studies but must not coerce play; ignore/no-interest is a valid, respected action and must never cause the soundtrack to ramp indefinitely.

**Hard gates**: verify real audio bytes, actual model name/hash, non-empty spoken samples and subtitles, correct on-device decoding and 3D positioning, unobtrusive fallback, no frozen camera while synthesizing, cache hit-rate, p50/p95 speaking-start delay and audio dropouts on Samsung-class device. A model merely being listed/installed is not synthesized audio.
