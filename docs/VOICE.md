# Neural NPC speech and measured player-speech path

The delivered baseline contains **23 genuine Piper speech clips**, three English speaker indexes and a Jordanian Arabic candidate. `artifacts/voice/catalog.json` is the client catalog. `data/voice/catalog.json` is its identical offline copy. Each clip has exact text/subtitle, semantic act, actor identity (`npc:0/1/2`), voice identity, model/config hashes, independent Opus content hash, WAV fallback, duration, byte count and measured synthesis time. Match the authoritative utterance by **exact text**, because `greet` and `clarify` have several variants. The three ambient sign/walk/haven lines and the eight intent replies match the authoritative world productions exactly.

English uses upstream `en_US-libritts_r-medium` speakers **0, 4 and 10** (amber, river, cedar). These are three actual model speaker identities, not pitch-shifted copies. The source dataset model card identifies CC BY 4.0. Arabic uses **ar_JO-kareem-low** with upstream Jordanian locale metadata; it synthesizes actual Arabic samples. The dataset model card links a repository without a clear license declaration, so its redistribution clearance remains unresolved. Ryan was downloaded as a contender but is excluded from the active catalog because its dataset card specifies CC BY-NC-SA 4.0; Amy/Lessac are also not active catalog voices. Source URLs, downloaded sizes, exact model hashes and pinned Hugging Face revision are in `data/voice/sources.json`. Preserve the attribution and upstream model cards. The models themselves are local, ignored build inputs; generated short speech clips and metadata are deliverable artifacts.

[C] The speech pipeline is `canonical world act → bounded production → exact-text validation → model/speaker/config-specific cache identity → Piper CPU → real PCM → ffmpeg Opus → independent content hash`. No LLM is required. The optional paraphraser is disconnected; unrecognized rewrites cannot invent facts or select effects. `validate_utterance` accepts only registered productions. This is a deliberately small bounded utterance grammar, not a general natural language fact checker. The cache key includes text, locale, phoneme/config revision, model hash, voice id, speaker index, rate, style, format and sample rate. Floating-point neural synthesis is not asserted to produce identical bytes on another backend; stored bytes have their own SHA256. Reusing already stored clips requires no inference. Preparation commits zero fictional world events, and `ambient_conversation` returns prepared possible schedules; the world authority decides which branch really happens.

[M] `evidence/voice_benchmarks.json` contains actual CPU measurements. The 23 clips contain 41.047 seconds of speech in 251,549 Opus bytes. Their historical median synthesis time was about 1.14s and p95 about 2.39s under the concurrent container workload; median real-time factor was about 0.60. A repeated preparation reused all 23 clips without changing audio bytes (100% cache hits). These are small offline sample measurements, not phone onset or Oracle throughput results. Runtime inference configuration now limits Piper to one intra-op/inter-op thread, with one work lock; historical catalog timings were collected before that thread cap, so no controlled speedup claim follows. Explicit builds, not server startup, perform corpus generation.

[M] Kokoro 82M ONNX int8 was actually downloaded, loaded and used to synthesize two English evaluation WAV files. `evidence/voice_kokoro_benchmarks.json` records source/content hashes, about 5.74s cold load, real-time factors about **6.86 and 3.77**, and about 344MiB process peak RSS in this container. It remains an offline quality contender. There is no human audition ranking or promise of real-time performance on the reported Oracle ARM64 machine. The exact local model is `kokoro-v1.0.int8.onnx` from the linked kokoro-onnx release; the onnx-community model named in the rider was a source candidate, not the executed binary.

The actual STT API is `transcribe_audio(audio_bytes, mime_type='audio/webm', locale='en-US')`. It decodes the uploaded capture through ffmpeg into 16kHz mono PCM, then invokes **sherpa-onnx 1.13.8**: Moonshine tiny int8 for English, Whisper tiny int8 for Arabic/multilingual requests. Captures are limited to 5MiB and 15 seconds; invalid formats are refused. One bounded work lock serializes inference. Busy requests produce a typed retry/clarify result. Audio and transcripts are discarded after the call unless a caller separately opts into retention. `confidence` is **null** because these backends expose no calibrated confidence; no invented confidence score is substituted. The result includes engine, actual timing, duration, RMS and a separate grammar-validated intent proposal. Neither transcript nor intent can run shell commands or privileged writes.

[M] Both models transcribed one bundled 6.625s reading fixture and a synthesized NPC greeting with **WER 0** after normalized punctuation/case. This is a tiny fixture result, not general accuracy. The warm English NPC sample took Moonshine about **0.893s** versus Whisper about **3.224s**, including audio decoding. A controlled 10dB white-noise fixture changed one of eight English words (WER **0.125**). The Arabic candidate failed one of three normalized words (**WER 0.333**); Whisper took about **21.99s** including its Arabic recognizer load and produced `مرحرون مساء الخير` for `مَرْحَبًا. مَسَاءُ الْخَيْرِ.`. This is an explicit counterexample to claiming the current multilingual path is release-quality Jordanian speech recognition. Native-speaker, spontaneous, colloquial and real traffic-noise Arabic evaluation remains unresolved. Out-of-grammar text returns in-world clarification rather than an effect. Cold/warm latency is recorded separately through `model_load_ms`; the test container was running other build work, and these are not isolated 2-vCPU comparisons.

The browser/Android client supplies push-to-talk and explicit microphone permission, keeps text/tap fallback, and spatially plays cached clips. Actual device capture, Samsung audio focus, process kill/resume, lip sync, headset direction, cache onset p95<250ms and dropout/power measurements require device/browser traces. Their status must come from that integration evidence, not these WAV tests. The reported Oracle node was not connected, so concurrency 1 vs 2, ARM64 model speed and existing Ollama/PURL/PostgreSQL health are **BLOCKED** here. No Oracle service was changed. The tiny 135M/360M optional Ollama paraphrase benchmark was not run; baseline gameplay has no model dependency.

Rebuild explicitly:

```bash
python -m pip install --target .cache/voice-python -r requirements-voice.txt
python tools/voice_fetch.py
python tools/voice_build.py
python tools/voice_benchmark.py
python -m unittest discover -s tests
```

`voice_fetch.py --include-evaluation` also retrieves rejected/evaluation contenders and Kokoro. It verifies every source hash and safely extracts ASR archives. `tools/voice_kokoro_benchmark.py` is an optional separate evaluation command. ffmpeg with `libopus` must be available. Models are not downloaded or synthesized automatically when the game starts. The active catalog can be served and played without the neural packages installed; player ASR needs the optional worker packages and retrieved models.
