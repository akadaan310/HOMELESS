# Geographic and celestial source adapters

`worldloom.geo` resolves the complete WGS84 coordinate address space and supplies real source topology in three acquired OSM windows. `worldloom.sky` resolves pinned HYG source stars and geometric observer visibility. Every response keeps source geometry separate from fictional aliases and gameplay overlays. The sky implementation and numerical limits are documented in [SKY.md](SKY.md).

```python
from worldloom import geo, sky
geo.overview()
geo.resolve_cell(27.95946425, -82.5055696, epoch="2026-10-20T19:15:00Z")
geo.route(city="tampa", mode="walk")
geo.scene(city="tampa", radius_m=700)
geo.match_routes("tampa", "london", seed=31, samples=128)
sky.observer(27.95946425, -82.5055696, at="2026-10-20T02:00:00Z")
sky.discover(seed=42, null_trials=99)
```

The actual Dale Mabry / Spruce intersection is the pair of shared OSM nodes `2057042478` and `1603574189` on both named roads. Its midpoint is **27.95946425, -82.5055696**. The pedestrian spawn is source footway node `4520926405`, at **27.9593434, -82.5054827**. This is a tag-based inference of public pedestrian access; live closures and legal access have not been inspected in the field. The source graph includes separate footways, crossings, traffic-signal points, lanes/turn-lane tags and directed road ways. It does not create surveyed lane polygons or sidewalk widths from missing information.

OSM API XML was downloaded on 2026-10-20. Exact request URLs, per-file SHA-256, HTTP response dates, license and attribution are in `data/geo/sources.json` and `data/geo/raw/*.headers`. All per-object versions and timestamps remain in normalized JSON; the unaltered downloaded XML remains alongside it. Data is © OpenStreetMap contributors, ODbL 1.0: https://www.openstreetmap.org/copyright . The normalized graphs contain 1,867/385/1,031 highway ways and 1,298/232/362 building footprints for Tampa/Marina/London respectively. The latter supplies a second continent for actual graph comparison.

The airport, port, populated-place and World Bank population fixtures were copied byte-for-byte from the preserved original `homeless-realms-0.1` inputs. Their hashes and expected source locations are recorded, with release and remote-revision uncertainty stated explicitly. Airport/port points are generalized Natural Earth reference features, not flight paths or shipping lanes. Settlement population estimates are sparse historical reference points; the country CSV retains source years. No local density or population raster is inferred from these sources. A downloaded Open-Meteo model snapshot contains actual Tampa forecast/model estimates for 2026-10-20 19:15 UTC. Responses always expose its timestamp, model status, spatial limit and staleness; it is never presented as a current station observation.

`data/geo/acquire.py` rebuilds normalization from retained inputs. `python data/geo/acquire.py --refresh` makes fresh OSM API requests; this intentionally changes source hashes and requires regenerating scene/witness evidence. Files under `masterpack/` and `upstream/` are unchanged. Natural Earth public-domain terms, World Bank CC BY terms and Open-Meteo CC BY terms are linked in the manifest. Overture, FAA airways, AIS/navigable lanes, WorldPop/GHSL grids, terrain, interiors and global detailed routing are explicit gaps.

Coordinate helpers use ellipsoidal WGS84 ECEF and orthonormal local ENU. They accept dateline wrapping, poles and below-sea-level ellipsoidal altitude. Earth-center conversion refuses an undefined position. `geographiclib==2.1` supplies Karney inverse geodesics, including antipodes. An optional dependency fallback implements Vincenty and labels its nonconvergent antipodal authalic-sphere fallback in the overview. ENU is a local render chart, not a flat global Earth. The zero-height scene origin is a chart choice, not surveyed terrain altitude. A renderer moves its chart continuously using the same ECEF position, avoiding coordinate resampling.

`TileStore` addresses the planet with an equirectangular quadtree, with longitude normalized to `[-180,180)` and polar rows clamped. It realizes small metadata recipes only on demand, maintains a bounded LRU (64 tiles by default), and does not fetch worldwide detail. Graph JSON is lazily loaded in a two-entry cache; mode adjacency has six entries; reference tables are small fixed source sets. Warm global queries use a spherical-chord shortlist followed by WGS84 refinement of generalized reference points. Source coverage masks are returned for every region, including poles, dateline and ocean queries. The global address space is supported independently of local source detail.

Walking follows actual allowed source edges and prefers a separate source footway for spawning. Private/no-access, construction, motorway and unapproved primary-road centerlines are excluded. Default routes are shortest paths to the farthest reachable node within the stated geodesic-distance budget; an explicit destination uses Dijkstra. Coordinate snaps are limited to 250 m and unsupported/disconnected routes return a reason. Source road directions are respected for driving and cycling. OSM turn-restriction relations are retained but not yet enforced: driving results carry an explicit illustrative-route limitation. This adapter is not a navigation or access-safety service.

Street comparisons normalize turns, junction degree and segment-length ratios after collapsing degree-two geometry samples. Each candidate has both actual source graphs, exact route nodes, chart/features, score, transform and content hash. A held-out null stream replays the same 16-candidate maximum selection, so calibration accounts for candidate search. These are local experimental structural correspondences. Geometric resampling and omitted building/POI/lane features are declared projection loss. A negative result remains negative; a portal is never inserted into physical topology.

Static browser recipes are `data/geo/{tampa,marina,london}-scene.json`. Roads and footprints refer to actual source way IDs. Each width and height says whether it came from a source tag, was estimated from lanes/levels, or was an artistic default. Building display aliases are deterministic fiction. Coordinates are `[east,north,up]` metres; PlayCanvas maps these to `[east,up,-north]`. Rendering quality is the renderer's responsibility, not implied by a valid source recipe.

Verification is reproducible with `python -m pytest tests/test_geo.py tests/test_sky.py -q`. Evidence includes source manifests, source routes, cross-continent calibration, coordinate residuals, broad-region coverage queries, bounded cache and latency measurements. `evidence/geo_repo_*` records read-only reconciliation of the live public `anwaa` and `MUSA` default branches: anwaa's pinned code is a Canvas2D physics/UI engine with celestial presentation, while MUSA's pinned tree is a Luna protocol/document staging program. Neither was substituted for measured Earth or star data.
